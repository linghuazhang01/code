# Candidate Pool Size Ablation 实验计划

**Problem**: 比较小型 VR Control/Structure V1/V2 pools 与 surface-level domaincand V1/V2 whitelists，决定 production selector 应使用哪种候选范围。
**Method Thesis**: 小池子若能保留大池子的 future-target coverage，应以更低噪声和成本获得相当或更好的 F1；surface pool 只有在其额外候选带来可重复的 end-to-end recall 与下游收益时才值得采用。
**Date**: 2026-08-31

## 当前判断

- **暂定 production default：小池子。**
- **Surface pool：coverage upper bound 与安全对照。**
- 目前不能直接定案：Top-30 在小池子约占 52%–91%，在 Surface pool 仅占约 14%–16%。必须同时报告 fixed-K、fixed-ratio 和共同 recall denominator。
- 若只有少量 surface-only token 稳定有价值，再测试 Small core + Surface backfill；它不是第一阶段主比较对象。

## 公平评价定义

对每个 domain，定义共同 universe 与 target：

\[
U_d=P^{surface,V1}_d\cup P^{surface,V2}_d,\qquad
T_{d,t}=U_d\cap \operatorname{GlobalFutureTop200}_{d,t}.
\]

Future Top-200 使用既定 start–end \(t\rightarrow t+5\) absolute logp-gap 净优化量，endpoint occurrence 均至少为 20。对 pool \(P\) 与选择 \(S\)：

\[
\text{PoolCoverage}=\frac{|P\cap T|}{|T|},\quad
\text{Precision}=\frac{|S\cap T|}{|S|},
\]

\[
\text{EndToEndRecall}=\frac{|S\cap T|}{|T|},\quad
\text{ConditionalRecall}=\frac{|S\cap T|}{|P\cap T|}.
\]

主分数用标准 \(F1=2PR/(P+R)\)，同时保留此前指定的 \(PR/(P+R)\)。两者只差常数 2，最优 rank/K/window 相同。

## Experiment Blocks

### B0: Membership 与 support sanity

- Data：1.7B-OPD、1.7B-EOPD、4B-OPD、4B-EOPD。
- 输出：size/hash、Small 是否为 Surface 子集、overlap/Jaccard、occurrence>20 的 step 分布、eligible pool size、small-only/surface-only target coverage ceiling。
- Success：全部 ID 可追溯且无 taxonomy namespace 混用。
- Failure：若 Small 不是 Surface 子集，按四个独立 pools 比较，不能解释为单纯扩池。
- Priority：MUST-RUN。

### B1: Offline selector 全网格 replay

- Systems：Small-V1、Small-V2、Surface-V1、Surface-V2。
- Fixed：interval=3、future horizon=5、start–end target、rolling mean occurrence≥20。
- Recoverable metrics：A、C、E*、F；B/D 标 N/A，不用 proxy 冒充。
- Window：每个整数 w=1…20。
- K：
  - fixed-K：K=1…min(60, PoolSize)；
  - fixed-ratio：按 K/PoolSize 画曲线，重点标记 10%、20%、30%、50%；
  - production points：K=20、30。
- Aggregation：先按 12 个 baseline×domain cells 汇总，再等权 macro；SD 仅为 descriptive variation。
- 输出：PoolCoverage、Precision、ConditionalRecall、EndToEndRecall、F1、K×window heatmap、PR-vs-K。
- Priority：MUST-RUN。

### B2: Surface-only token 价值分解

- 对象：Surface minus Small。
- 统计：
  - 进入 Future Top-200 的次数和跨 baseline 稳定率；
  - occurrence>20 至少 2/3/5 steps 的 token 数；
  - selection count、hit count、hit/selection ratio；
  - end-to-end Recall 增量；
  - token type×domain 分解。
- Success：额外收益必须来自跨多个 boundary/baseline 可重复的 hits。
- Failure：新增 IDs 大量 eligible 却极少命中，说明主要增加 ranking noise。
- Priority：MUST-RUN。

### B3: 公平性与鲁棒性

- fixed-K vs fixed-ratio；
- occurrence threshold 10/20/30；
- repeated-support requirement 1/2/3/5 steps；
- leave-one-baseline-out；
- domain macro vs micro；
- selection Jaccard 与 boundary-to-boundary churn。
- 若结论只在某个 denominator、K 或单条 baseline 成立，标为 inconclusive。
- Priority：MUST-RUN。

### B4: Exact D 与最终训练确认

- 新 audit 落盘 response-level normalized reverse-KL、Student Entropy、D score、eligible IDs 与 selected IDs；不能从旧 aggregate vectors 反推。
- Shortlist：offline 最佳 Small、offline 最佳 Surface；仅当 surface-only 稳定有价值时加入 backfill。
- Control：相同 checkpoint、data order、batch、interval、window、K 与训练预算。
- Run：1.7B smoke → 1.7B 三 seeds → 结论成立后 4B confirm。
- Primary：Math/Code/Science terminal ACC、loss start–end 净下降、loss optimization speed。
- Secondary：selector latency、candidate scoring time、peak memory、selection churn。
- Success：selector 改善转化为至少两个 domain 的一致下游改善，且无 domain 明显退化。
- Priority：修改 production config 前 MUST-RUN。

## 决策规则

1. **选 Small**：共同-denominator end-to-end F1 与 Surface 基本持平，三个 domain coverage loss 很小，同时计算量显著下降。
2. **选 Surface**：surface-only tokens 带来跨 baseline 稳定 Recall 增益，并在 exact-D/训练中改善 ACC 或 loss speed。
3. **选 Hybrid**：只有少量 surface-only token 稳定有价值，而全量 Surface 降低 Precision 或增加 churn。
4. **不下结论**：优势只来自 pool-specific denominator、单 trajectory 或单一 K/window。

第一轮分析前需把“基本持平”“很小”“显著”量化为 absolute margin 并写入 run contract，不能看完结果再定阈值。

## Must-run / Nice-to-have

**Must-run**：B0–B3；若要更改 production config，B4 也必须完成。

**Nice-to-have**：adaptive backfill、每 domain 独立 K、token case study、训练中动态 pool expansion。

## Risks

- denominator 随 pool 改变：主结果固定 Surface-union target。
- Top-30 对 Small 近乎 exhaustive：同时做 fixed-K 与 fixed-ratio。
- B/D 缺失：旧数据只分析 recoverable metrics，最终用 exact-D audit。
- 单 trajectory：12-cell 描述后，用 3-seed training 决策。
- 网格搜索偏差：区分探索 optimum 与预注册 production point。
